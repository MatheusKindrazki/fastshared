# FastShared App Store launch setup

This is the operational checklist for moving FastShared from TestFlight to a
public App Store launch. Versioned metadata lives in `apple/fastlane/metadata`;
screenshots are generated by XCUITest/ImageRenderer, and fastlane uploads the
store configuration from this repo.

References verified on 2026-04-24:

- Apple screenshot specifications:
  https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications
- Apple app information reference:
  https://developer.apple.com/help/app-store-connect/reference/app-information/app-information
- Apple app privacy management:
  https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy

## Fastlane commands

Bootstrap fastlane once:

```bash
make testflight-bootstrap
```

Verify local store config and API key:

```bash
make appstore-doctor
```

Generate all App Store screenshots locally:

```bash
make appstore-screenshots
```

This produces:

- 5 iPhone 6.9 inch screenshots.
- 5 iPad 13 inch screenshots.
- 5 macOS screenshots.
- 1 IAP review screenshot copied from the Pro paywall capture.

Upload privacy details, metadata, app icon, age rating, and screenshots without
submitting:

```bash
make appstore-sync
```

Upload metadata only, reusing existing screenshots, if recovering a failed
metadata upload:

```bash
make appstore-metadata
```

Upload only one platform if recovering a failed upload:

```bash
make appstore-metadata-ios
make appstore-metadata-macos
```

Upload App Privacy only:

```bash
make appstore-privacy
```

Submit to App Review after metadata, screenshots, IAPs, privacy, and processed
builds are ready:

```bash
cp apple/.env.appstore.example apple/.env.appstore.local
$EDITOR apple/.env.appstore.local
make appstore-submit
```

The submit lane refuses to run unless `FASTSHARED_SUBMIT_FOR_REVIEW=YES`.

## App Store Connect app record

Create or confirm one app record:

- Name: `FastShared`
- Bundle ID: `dev.kindrazki.fastshared`
- SKU: `fastshared-ios-macos-1`
- Platforms: iOS/iPadOS and macOS on the same App Store app record
- Primary language: English (U.S.)
- Category: Productivity; secondary Utilities

Do not create separate App Store app records for the share extension or Live
Activity. Those are Apple Developer portal Identifiers/capabilities, embedded
inside the main app build.

## Screenshots

Screenshots are generated; do not capture them manually.

```bash
make appstore-screenshots
```

The screenshot lane:

- regenerates `FastShared.xcodeproj`;
- runs `FastSharedAppUITests/AppStoreScreenshotsUITests` on an iPhone
  simulator;
- runs the same test on an iPad simulator;
- builds the macOS app and exports deterministic Mac shots directly via
  SwiftUI `ImageRenderer`;
- copies the Pro paywall shot into the IAP review screenshot folder;
- validates counts and pixel dimensions before exiting.

Generated files land here:

- `apple/fastlane/screenshots/ios/en-US/`
- `apple/fastlane/screenshots/macos/en-US/`
- `apple/fastlane/screenshots/iap/en-US/`

Required anchors for this app:

- iPhone 6.9 inch: `1260x2736`, `1290x2796`, or `1320x2868` portrait.
- iPad 13 inch: `2064x2752` or `2048x2732` portrait.
- Mac: `1280x800`, `1440x900`, `2560x1600`, or `2880x1800`.

Use 1-10 screenshots per display set. Recommended order: share flow,
retention picker, progress/Live Activity, history/revoke, Pro paywall.

Simulator/device selection can be overridden without editing the Fastfile:

```bash
FASTSHARED_SCREENSHOT_IPHONE_DESTINATION='platform=iOS Simulator,name=iPhone 17 Pro Max,OS=latest' make appstore-screenshots
FASTSHARED_SCREENSHOT_IPAD_DESTINATION='platform=iOS Simulator,name=iPad Pro 13-inch (M5),OS=latest' make appstore-screenshots
FASTSHARED_SCREENSHOT_MAC_DESTINATION='platform=macOS' make appstore-screenshots
FASTSHARED_SCREENSHOT_MAC_EXPORT_TIMEOUT=120 make appstore-screenshots
```

## App Privacy answers

Set the privacy policy URL first: `https://fastsha.red/privacy`.

Tracking:

- Used for tracking: No.
- Third-party advertising: No.
- Advertising ID: No.

Data types to disclose:

| Data type | Linked to user | Tracking | Purpose |
| --- | --- | --- | --- |
| User Content > Other User Content (uploaded files) | No | No | App Functionality |
| Identifiers > User ID (device token hash / optional Apple subject ID) | Yes | No | App Functionality, Account Management |
| Contact Info > Email Address (optional Sign in with Apple relay email) | Yes | No | App Functionality, Account Management |
| Purchases > Purchase History (Pro entitlement records) | Yes | No | App Functionality |
| Diagnostics > Other Diagnostic Data (request logs, redacted app logs) | No | No | App Functionality, Analytics, Fraud Prevention |

If App Store Connect asks whether uploaded file bytes are optional disclosure:
do not omit them. Uploading user-selected files is the product's core
functionality, so the App Privacy label should disclose User Content.

## Age rating

The fastlane rating config lives at `apple/fastlane/app_rating_config.json`.
It declares all content descriptors as `NONE`, no unrestricted web access, and
`userGeneratedContent = true` because FastShared creates private links to
user-provided files. There is no public feed, chat, comments, or discovery.

## IAP products

Configure Pro exactly as in `docs/marketing/asc-runbook-pro.md`.

The repo now generates the IAP review screenshot automatically at
`apple/fastlane/screenshots/iap/en-US/01_APP_IPHONE_67_iap-pro-review.png`.
The product records themselves are still constrained by App Store Connect
account state: Paid Apps Agreement, tax, banking, and first-time IAP product
creation may require an account owner/admin action in Apple's UI before API
automation can update or submit them.

Canonical product IDs:

- `red.fastsha.pro.annual`
- `red.fastsha.pro.lifetime`
